# Contributing to TechForge

Thanks for helping out. You don't need to be an expert. Every TechForge project has work for beginners, and asking questions is part of the job.

## Ways to help

- **Code:** fix a bug or build a small feature.
- **Art and sound:** skins, textures, icons, music.
- **Writing:** READMEs, guides, comments, in-game text.
- **Testing:** try things, then open an issue when something breaks.
- **Ideas:** open an issue with the **Idea** form.

## Find something to work on

1. Look for issues labeled [`good first issue`](https://github.com/search?q=org%3Atechforge-cwi+label%3A%22good+first+issue%22+state%3Aopen&type=issues).
2. Comment "I'd like to take this" so nobody else starts on the same thing. An officer will assign it to you.
3. Stuck for more than 20 minutes? Ask in the project's Discord channel. No question is too basic.

Never made a pull request before? Do [hello-techforge](https://github.com/techforge-cwi/hello-techforge) first. It takes about 10 minutes and teaches the whole process.

## How a change gets in

Every change goes through a **pull request (PR)**. You can't push straight to `main`, so you can't break anything by trying.

1. **Fork** the repo (button at the top right). If you're on the project's team, you can make a **branch** in the repo instead.
2. Make your change in **small commits** with clear messages, like `Add sheep-counting command` rather than `stuff`.
3. Open a **pull request**. Say what you changed and why, add screenshots if it's visual, and write `Closes #12` to link the issue.
4. An officer or teammate **reviews** it. Comments are normal and not a bad sign. Push more commits to the same branch, and the PR updates by itself.
5. Once it's approved, an officer **merges** it.

## Ground rules

- **Never commit passwords, API keys, or tokens.** Put them in a `.env` file and make sure `.gitignore` lists it. If you commit one by accident, tell an officer right away (see [SECURITY.md](SECURITY.md)).
- **Only add things you have the right to share.** That means your own work, or code, art, and data whose license allows it. Credit your sources.
- **AI tools are welcome** (we're an AI club). You're responsible for understanding and testing anything you submit, so mention in the PR what you used them for.
- **Be kind in reviews.** Ask questions instead of making demands, and remember everyone here is learning.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).
